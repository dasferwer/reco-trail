# RecoTrail

[![CI](https://github.com/dasferwer/reco-trail/actions/workflows/ci.yml/badge.svg)](https://github.com/dasferwer/reco-trail/actions)

Сервис рекомендаций фильмов с историей действий и воспроизводимой оценкой качества.
Новый пользователь получает популярные фильмы или подборку по выбранным жанрам.
После обратной связи выдача учитывает его историю. Повторный запрос не создаёт
второе событие, а запоздалый просмотр не отменяет более свежий дизлайк.

Учебный проект уровня Middle+ Backend + ML. Python 3.12, FastAPI, PostgreSQL 17,
SQLAlchemy, NumPy; обучение — scikit-learn. Модель включена в репозиторий,
для запуска не нужны внешние ML API или GPU.

## Запуск

```bash
docker compose up --build -d --wait --wait-timeout 180
make smoke
```

Swagger: <http://localhost:8160/docs>. PostgreSQL доступен только внутри Docker.

| Пользователь | Пароль | Назначение |
|---|---|---|
| `demo@example.com` | `RecoTrailDemo123!` | Профиль с 40 событиями из обучающей истории |
| `admin@example.com` | `RecoTrailDemo123!` | Каталог и версии модели |

В Swagger выполните `POST /auth/login`, скопируйте `access_token` в **Authorize**.
Затем откройте `GET /recommendations`. Для холодного старта создайте новый аккаунт
через `POST /auth/register`.

## Что показать

1. Получить рекомендации нового аккаунта. Без истории и жанров используется популярность.
2. Прочитать `GET /me`, взять `ETag` и передать его в `If-Match` при `PUT /me/preferences`.
   Например, `{"genres": ["Horror", "Mystery"]}` изменит подборку.
3. Отправить `POST /events` с `Idempotency-Key: demo-like-1` и телом
   `{"item_id": 1, "kind": "like"}`. Фильм исчезнет из следующих рекомендаций.
4. Повторить запрос с тем же ключом: вернётся прежний `event_id`, версия профиля не увеличится.
5. Посмотреть `GET /events` и сравнить `algorithm=popularity`, `content`, `collaborative`, `hybrid`.
   По умолчанию `auto` выбирает алгоритм, победивший на validation.

Фильмы: `GET /items`, жанры: `GET /genres`. `score` служит для сортировки внутри
одной выдачи и не является вероятностью. Пояснения жанров показывают совпадения
с интересами пользователя, а не измеренный вклад каждого признака в результат SVD.

## Backend

- Событие, актуальное состояние интереса и версия профиля фиксируются одной транзакцией.
  Конкурентные записи одного пользователя упорядочены блокировкой его строки.
- Ключ повторного запроса принадлежит пользователю. Изменённое тело с тем же ключом даёт `409`.
- Позднее событие сохраняется с `applied=false`. При равном времени побеждает записанное
  позже. Допускается расхождение часов на 30 секунд вперёд.
- Предпочтения обновляются через `If-Match`: отсутствие заголовка даёт `428`, устаревшая версия — `412`.
- Выдача читает профиль, историю, каталог и модель из одного снимка PostgreSQL.
  Кэш на 256 выдач учитывает пользователя и версии профиля, каталога и модели.
- Администратор добавляет и скрывает фильмы. Новый фильм может участвовать в подборке
  по жанрам до следующего обучения. Демокаталог ограничен 10 000 строками.
- Модели регистрируются локальной командой и переключаются через API. JSON и NumPy-массивы
  проверяются по SHA-256; pickle при загрузке не используется.
- Есть JWT, раздельные права, пагинация, `/health`, `/metrics`, идентификатор запроса.
  Runtime работает без root, pytest, Ruff и scikit-learn.

## Модель и качество

Зафиксирован снимок MovieLens latest-small: 100 836 оценок, 610 пользователей,
9 742 фильма в исходном каталоге. Serving использует 8 586 фильмов, известных
до тестового периода. SHA исходных файлов — в [data/source.json](data/source.json).

Разбиение **по общему времени**: 80 668 событий train, 10 084 validation,
10 084 test. Популярность и SVD не видят будущих событий. Параметр смеси и алгоритм
выбраны на validation, после чего факторы переобучены на train + validation.

| Алгоритм | Recall@10 | NDCG@10 |
|---|---:|---:|
| Популярность | 0.03790 | 0.09590 |
| Жанры | 0.01015 | 0.04375 |
| Collaborative SVD | 0.05964 | 0.15715 |
| Hybrid, выбран на validation | 0.05525 | 0.16482 |

Это macro-метрики на **25 пользователях с положительной историей**, имеющих
доступные релевантные фильмы в тесте. Для 47 пользователей без положительной
истории все алгоритмы используют популярность: Recall@10 0.09550, NDCG@10 0.39429.
652 из 4 128 будущих положительных событий относятся к неизвестным на cutoff
фильмам: они отражены отдельно и не входят в знаменатель Recall@10.
Использован весь известный каталог без подвыборки отрицательных примеров.

Небольшая историческая выборка показывает работу сравнения моделей, но не доказывает
рост CTR или качество на другом каталоге. Протокол и ограничения — в
[model-card](docs/model-card.md), все эксперименты — в
[evaluation.json](models/movielens-v1/evaluation.json).

## Проверки

```bash
make check
make test
make smoke
uv run python scripts/recovery_smoke.py
```

24 теста проверяют транзакции, конкуренцию, кэш, права и пересчёт метрик.
Проверка восстановления отправляет событие, завершает API через SIGKILL,
запускает его снова и повторяет запрос: остаётся одно событие, выдача совпадает
с результатом до перезапуска. Тесты используют отдельную временную базу.

Проект выполняет точное ранжирование небольшого каталога. Для роста нагрузки
нужны отдельный отбор кандидатов, общий кэш и нагрузочные измерения.
Действия меняют профиль сразу, но не переобучают глобальные факторы:
CLI читает исходный MovieLens, а не события API. A/B-тесты и сбор показов
для оценки CTR в проект не входят.
