# Отдельные группы и ресурсный замер RecoTrail

Команда: `uv sync --extra dev --frozen && uv run python -m scripts.evaluate_groups`.
Полные значения и ошибки каждого пользователя: [p2-ranking.json](p2-ranking.json).
Используется существующая численная модель `movielens-v1`, её manifest SHA-256 записан в отчёте. Параметры и default algorithm выбраны ранее на validation; здесь модель не обучается и test labels не используются для выбора параметров.

Данные — замороженный MovieLens latest-small из GroupLens. Файлы, официальный URL и контрольные суммы сохранены в `data/source.json`; `read_data` проверяет все три файла, включая исходный `README.txt`. Условия использования MovieLens остаются в `data/README.txt`: исследовательское использование, указание авторов, сохранение этих условий при распространении, коммерческое использование требует разрешения GroupLens. Код проекта под MIT не меняет лицензию данных. Источник: F. Maxwell Harper and Joseph A. Konstan (2015), The MovieLens Datasets: History and Context, https://doi.org/10.1145/2827872.

Это повторная детализация исходного независимого temporal holdout, а не новый внешний набор. Прошлое включает train+validation; весь каталог модели состоит ровно из фильмов с событиями до test cutoff. Будущие фильмы и будущие оценки не участвуют в факторах/популярности. Релевантны test ratings >=4; уже оценённые и отсутствующие в замороженном каталоге фильмы исключены. Все отрицательные оценки прошлого также исключаются из рекомендаций. Warm означает хотя бы одну положительную оценку прошлого, cold — отсутствие положительных; cold может иметь отрицательную историю. Нет sampled negatives. Метрики усредняются по пользователям с хотя бы одним доступным релевантным фильмом, а не по всем пользователям исходных данных.

| Группа, hybrid | Пользователей | Релевантных фильмов | Попаданий @10 | Пропущено | Пользователей без попадания | Recall@10 | NDCG@10 |
|---|---:|---:|---:|---:|---:|---:|---:|
| warm | 25 | 764 | 38 | 726 | 12 | 0,05525 | 0,16482 |
| cold | 47 | 2712 | 165 | 2547 | 9 | 0,09550 | 0,39429 |

Warm popularity NDCG@10 = 0,09590, collaborative = 0,15715, content = 0,04375. Cold все четыре алгоритма переходят к одному popularity fallback и дают одинаковые значения. Малые группы не подтверждают переносимость/CTR. Высокая cold NDCG не означает лучшую персонализацию: у группы другой набор релевантных фильмов и нет персональных положительных событий. По hybrid 12/25 warm пользователей не получили ни одного попадания. Даже положительный средний результат не устраняет эту ошибку.

Каталог ресурсного замера: 8586 реальных позиций модели + 1414 явно синтетических позиций с одним случайным жанром (seed 216), всего 10000. Синтетические позиции не имеют обученных факторов и популярности; это только проверка объёма, не проверка качества. 100 seen (включая нулевой вес) и 100 непересекающихся inactive оставляют ровно 9800 кандидатов. Полное ранжирование сверяется с этим множеством; top-10 повторов детерминирован и не содержит excluded ID. Версия модели одинакова при оценке качества и замере.

Локальная машина Apple M4 Pro, 12 логических CPU, macOS 27.2 arm64, Python 3.12.13, NumPy 2.5.3, threadpool limit 2, concurrency 1. После пяти прогревов 100 вызовов `Model.rank`: p50 **10,18 мс**, p95 **13,14 мс**, max **24,45 мс**, CPU **1,04 с**. Отдельный проход tracemalloc: peak **5840712 байт**; lifetime process peak RSS **194478080 байт** включает импорт, загрузку и evaluation. Tracemalloc не включён в измерение задержки. Возможна конкуренция с другими процессами машины; значения не SLA. HTTP, БД, cache и загрузка модели исключены из этого бюджета. Дополнительное online обучение или новая инфраструктура из этих замеров не обоснованы.
