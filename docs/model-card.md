# Модель рекомендаций

MovieLens latest-small, снимок от 26 сентября 2018 года, с зафиксированными SHA.
Источник и условия: [README GroupLens](../data/README.txt). Название latest-small
не означает, что данные современные. Модель предназначена для учебной демонстрации.

## Протокол

Общие временные границы — 80% и 90% отсортированных событий. Одинаковые timestamps
не делятся между частями. Доступный каталог строится по событиям до границы;
популярность и факторы не используют будущие оценки. Жанры взяты из статического
movies.csv: исторических версий метаданных в наборе нет.

Для пары пользователь/фильм берётся последняя оценка до cutoff.
Вес `max(rating - 3, 0)`. Неположительные веса сохраняют факт знакомства с фильмом,
но не добавляют положительных признаков. Матрица разреженная.

SVD: 32 компоненты, 7 итераций, seed 42. Факторы фильма — столбцы правой матрицы
разложения; профиль — взвешенная сумма факторов истории. Их скалярное произведение
даёт collaborative score. Контент — нормированные векторы жанров фильма и истории.
Выбранный жанр добавляет 3 к профилю. Популярность — число пользователей
с положительным весом до cutoff, после log1p.

Компоненты нормируются в [0, 1] по каталогу.
Hybrid = 0.95 × (alpha × collaborative + (1 − alpha) × content) + 0.05 × popularity.
Content и collaborative также получают 5% популярности. Без истории предпочтения
дают 95% content + 5% popularity, без предпочтений используется popularity.
У нового фильма нулевые факторы и популярность, но есть жанры.

Дизлайк исключает фильм, но не штрафует похожие жанры. Оценки MovieLens и сигналы
view/like/dislike имеют разные шкалы; offline-метрики не проверяют эту продуктовую
интерпретацию. Для неё нужны собственные данные взаимодействий.

## Выбор алгоритма

На validation перебраны alpha 0, 0.25, 0.5, 0.75, 1. Победил 0.75 по NDCG@10
на пользователях с положительной историей. Затем на validation сравнили четыре
алгоритма и выбрали hybrid. После этого факторы переобучены на train + validation,
а test использован для окончательного отчёта.

Для пользователя релевантны будущие оценки не ниже 4 по доступным на cutoff
фильмам, отсутствующим в прежней истории. Пользователи без таких фильмов не входят
в среднее. Выдача строится один раз, без подмешивания событий тестового периода.

Recall@10 — доля доступных релевантных фильмов, попавших в десятку.
NDCG@10 использует бинарную релевантность, скидку `1 / log2(position + 1)` и
нормировку на идеальную десятку. Усреднение — по пользователям.
Coverage — доля каталога хотя бы в одной выдаче среди обеих групп пользователей.
Использован полный каталог без sampled negatives. Неизвестные на cutoff фильмы
отдельно посчитаны в `future_items_unavailable`: 652 из 4128 положительных событий.

Hybrid: Recall@10 0.05525, NDCG@10 0.16482 на 25 тёплых пользователях.
У collaborative выше Recall@10 (0.05964), у hybrid выше NDCG@10 — сохраняем оба
критерия. Для 47 холодных пользователей популярность даёт NDCG@10 0.39429.
Группы имеют разные истории и релевантные множества, их значения не доказывают
превосходства холодного старта.

## Ограничения

Тёплая группа мала, доверительные интервалы не оценены. В данных нет показов,
пропусков и случайного распределения трафика. Recall/NDCG не измеряют CTR,
удовлетворённость или коммерческий эффект. latest-small — development dataset,
не общий стабильный benchmark; для повторения здесь зафиксированы конкретные байты.

Тесты пересчитывают опубликованные метрики из CSV. `uv.lock` фиксирует зависимости.
При новом обучении на другой BLAS-платформе возможны малые численные отличия.
Serving читает сохранённые факторы и не обучается на старте.
