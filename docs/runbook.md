# Запуск и обслуживание

```bash
docker compose up --build -d --wait --wait-timeout 180
make check
make test
make smoke
uv run python scripts/recovery_smoke.py
docker compose --profile test stop test-db
```

Тесты используют временную базу `recotrail_test`. Демоданные живут в Docker volume
`postgres_data`. `docker compose stop` сохраняет их; `docker compose down -v`
удаляет том и подходит только для сознательного сброса демоданных.

На хост опубликован только API, на 127.0.0.1:8160. Для внешнего размещения задайте
свой `JWT_SECRET`, измените демопароли и настройте TLS и ограничение запросов
на входном прокси. Compose содержит явные учебные значения.

## Диагностика

Сверьте `profile_version` в `/me` и `/recommendations`, модель в `/health`,
заголовок `X-Recommendation-Cache`, наличие события в `/events`.
`applied=false` означает, что событие старше актуального действия.
Повтор ключа возвращает результат первого запроса, не обязательно текущую версию.

Логи: `docker compose logs --tail=100 api`. Метрики: `/metrics`.
Email и история не записываются в логи HTTP-запросов.

## Обучение и переключение

```bash
uv sync --extra dev --frozen
uv run python scripts/train.py --version movielens-v2
```

CLI проверяет SHA исходных CSV и создаёт новую папку с весами, manifest и отчётом.
Существующую папку не перезаписывает. Повтор на тех же данных проверяет процесс
поставки и сам по себе не означает улучшение. События API этот CLI не импортирует.

После проверки метрик включите артефакт в образ:

```bash
docker compose build api
docker compose up -d --no-deps --wait api
docker compose exec -T api python scripts/register_model.py movielens-v2
```

В Swagger под администратором вызовите `POST /models/movielens-v2/activate`.
`GET /models` показывает активную версию. Для отката активируйте `movielens-v1`.
Новый каталог модели автоматически не импортируется: доступные фильмы управляются
через API. Изменение списка жанров требует отдельной миграции.

Не меняйте файлы зарегистрированной версии: SHA закреплены в базе, проверенная
модель кэшируется процессом. Для новых весов используйте новое имя.

## Восстановление

После перезапуска API кэш заполняется из PostgreSQL. Повтор неоднозначно
завершившегося запроса должен использовать тот же ключ и тело, включая время.

`recovery_smoke.py` завершает только API этого проекта через SIGKILL после
подтверждённого события, восстанавливает контейнер и сверяет единственность записи
и совпадение выдачи. Сбой внутри транзакции отдельно моделируется ошибкой PostgreSQL
перед обновлением профиля. Потерю тома базы этот сценарий не проверяет.

Для резервной копии используйте `pg_dump` и сохраняйте те же каталоги моделей.
Восстановленная база ожидает исходные SHA зарегистрированных артефактов.
